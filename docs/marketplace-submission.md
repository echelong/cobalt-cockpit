# Submission preparation — 0.3.2

Source repository: `https://github.com/echelong/cobalt-cockpit`.
Plugin folder: repository root. Version: `0.3.2`. Planned GitHub release tag: `v0.3.2`.
Name: Cobalt Cockpit. Identifier: `cobalt-cockpit`. License: MIT.
Use the manifest description as the listing description.

The repository includes a self-hosted marketplace named `cobalt-cockpit` for GitHub installs. Its root-relative `./` source installs this plugin; function commands are registered by the hooks module, not Markdown commands. Six bundled agents select their own model and reasoning level. There are no MCP servers, credentials, package launchers or extra permission grants.

Checked against Claude Code 2.1.294 and the current [mod documentation](https://code.claude.com/docs/en/plugins/mods/overview), [manifest reference](https://code.claude.com/docs/en/plugins/manifest-reference), [pre-submission checklist](https://claude.com/docs/plugins/pre-submission-checklist) and [submit guide](https://claude.com/docs/plugins/submit). The directory findings, what could not be reproduced locally and the external-behaviour inventory are in [implementation-v0.3.2.md](implementation-v0.3.2.md); read that document before opening the portal.

After publication and explicit owner approval, use [the developer portal](https://claude.ai/directory/manage) to validate the published source and submit the plugin bundle. The portal validates additional rules and name availability; local validation cannot certify acceptance. The official `claude-plugins-official` marketplace does not take submissions through this portal; its listing route requires an Anthropic partner contact.

This is a Claude Code mod. Its HUD and function commands do not run in claude.ai or Cowork. Two synthesized WAV cues are bundled binary files, so the checklist indicates a manual-review hold: they are generated by `assets/sounds/make-sounds.py`, read (never written) at runtime, optional, and silent when no player answers. The listing icon is in place: a 1024×1024 PNG rendered from VECTOR's own HUD portrait by `scripts/make-icon.py`, named by the manifest's `icon` field, with no metadata and no stock art. It is regenerated, not designed, so a reviewer can reproduce it byte for byte.
