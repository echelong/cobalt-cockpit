# v0.6.6 Git hardening: Stages A and B (unreleased)

> Part of the [Cobalt Cockpit documentation](README.md). Status: **Stages A and B, on a feature branch, not released.** The manifest still says 0.6.5; nothing here is published until the real-Git acceptance is done and a release is approved.

Two possible gaps were found in the released measurement (0.6.5):

- **Submodules.** Cockpit's `status` and `diff` examined submodules (`diff.ignoreSubmodules=none`, `--ignore-submodules=none`). A submodule's own configuration can make such a command run a program the repository chose (a clean filter, measured on Git 2.47.3 with a patch-shaped diff and with `status`; an earlier run on 2.43.0 with another setup did not reproduce it). The only gitlink check before those commands read one commit's tree.
- **Partial clones.** Nothing kept Git from lazily fetching a missing object, which runs the promisor remote's transport program (measured: a raw diff with a missing base blob ran a repository-configured `uploadpack` program). SECURITY.md already named the fetch as a residual of a helper's `*` inspection.

Each needs write access to the repository's Git configuration, which already gives code execution through the person's own Git use. What Cockpit added was automatic triggering: its hooks measure the tree after every tool call of the main session, at a prompt, at a Stop and for the HUD. Whether the released 0.6.5 argv reaches either state on real Git is not established; Stage A does not depend on it, because it refuses those states before any such command and pins every command. A third gap was left by Stage A and closed by Stage B: every measurement process inherited the host's whole environment (Git's own variables, the dynamic loader's, exported shell functions), and a helper's rebuilt inspection the Bash tool's.

## What Stage A changes

**Every measurement process (Cockpit's own Git, through `bounded`).**

| Change | Where |
| --- | --- |
| `GIT_NO_LAZY_FETCH=1` and `GIT_ALLOW_PROTOCOL=cockpit-none`, laid over the caller's environment **last**, so no caller can take them back | `BOUND_PINS` (`hooks/git-integrity.ts`), `bounded` |
| `diff.ignoreSubmodules=all` and `submodule.recurse=false` in `GIT_SAFE`; every `status` and `diff` with `--ignore-submodules=all` | `GIT_SAFE`; the release check, the HUD, the fingerprint |
| **Admission** before anything starts: only `git`, `stat`, `find`, `readlink` and `realpath`; `find` only in its two forms (no `-exec`, `-delete` or `-fprint`); for Git, only the pre-subcommand words Cockpit writes (the `-c` settings of `GIT_SAFE` and no other, one `-C`, the three safe flags); a closed discovery list (where the repository and its files are, configuration, `rev-parse --verify HEAD` without a peel, `--version`) runs freely; `status`, `diff`, `ls-files`, `ls-tree`, `hash-object`, `check-attr` and a commit peel need **a pass for their `-C` root**; any other Git subcommand (a fetch, `submodule`, `gc`, another configuration form) is never started. (Stage A did not check the arguments of an admitted subcommand; Stage B admits each only in its exact forms, below.) | `admissionRefusal`, `gitCallOf`, `gitAccessOf`, `nonGitAdmitted` |
| The repository-state check (`repoState`): configuration in every scope (`config --null --list`), promisor packs, gitlinks in the index's stage entries, and gitlinks in any commit compared without being measured. Every answer must be complete: a failure, a cut, stderr or a non-zero exit is "unreadable", never "absent". It returns a pass, an object it creates and records in a module-private `WeakSet`; an object with the same fields made anywhere else is refused | `repoState` |
| The clean/process filter drivers come from a complete configuration read: the check's, held in the pass, and a fresh one right before the `status` or `diff` of a fingerprint or a release check. The filter check no longer reads "no filter" from an exit status a signal could have produced | `gitFiltersReliable` |
| The check runs before any state-reading Git command at every measuring routine, and again after a fingerprint or a release check (`repoMoved`): a gitlink, a partial clone or a filter driver that appeared meanwhile gives no answer | the fingerprint, the release check, the HUD, helper inspection |

**A helper's Git inspection (rewritten by Cockpit, run by the host's Bash tool; orchestration only).**

- The same repository check before the command is allowed: the index, and HEAD's tree when HEAD is a commit. Only Git's own words for a repository with no commit yet ("Needed a single revision", read in the C locale) skip HEAD's tree, which does not exist then; any other failure refuses. For a scoped command also each revision it names, after it is proved a commit. A refusal names the reason and points to Read and Grep.
- Refused where Cockpit's environment sets a Git variable that moves where Git looks, what it reads, what it runs or where it writes. This is a list of known names (`GIT_ENV_REFUSED`, 39 since Stage B), read by literal name and only whether set; since Stage B the rebuilt command itself starts Git with a clean environment (below).
- Every rebuilt command, a `*` one too, is pinned with `-C` to the verified session directory, whatever directory the helper's shell is in, and carries `diff.submodule=short`, `protocol.allow=never` and `never` for each protocol, and `--ignore-submodules=all` on `diff`, `status`, `log` and `show`.
- An option that examines or recurses into a submodule (`--submodule…`, `--ignore-submodules…`, `--recurse-submodules…`, and their abbreviations) is no inspection, in either rule.

**Visibility.** The refusal words are closed (`REPO_REFUSAL_WORDS`), and the two a person can act on say what can be measured instead. The HUD shows `not measured (submodule | partial clone | state unreadable | unsafe Git inputs | active filter)`, never `clean`; a `status` that failed, was cut short or warned on stderr is `state unreadable`, never a count; a refresh that finishes after a newer one does not write over it. The Run Ledger's checkpoint and export record such a tree's change count as unknown. The release check's refusal names a repository Cockpit does not measure among its causes. `/cockpit doctor` names the Git version, as a warning when it is older than 2.45 or unknown.

## What Stage B changes

**A clean start for every measurement process.** The host lays a process's `env` over its own environment and cannot take a variable away (measured), so a Stage A measurement process saw the host's whole environment: `GIT_DIR`, `GIT_CONFIG_*`, `GIT_EXEC_PATH`, `LD_PRELOAD`, a `PATH` with relative entries, and, for a shell that imports them, exported functions (one named `ulimit` would have replaced the builtin the limit script relies on). Since Stage B each starts as

```
/usr/bin/env -i PATH=<absolute entries> [HOME=…] [XDG_CONFIG_HOME=…] MALLOC_ARENA_MAX=2 [LC_ALL=C] GIT_NO_LAZY_FETCH=1 GIT_ALLOW_PROTOCOL=cockpit-none \
  /bin/sh -c <the limit script> cockpit-bounded <seconds> [<GNU timeout by absolute path>] <the program by absolute path> <its words>
```

| Change | Where |
| --- | --- |
| `argv[0]` is the absolute `/usr/bin/env`, so the host looks nothing up (how it would resolve a bare name is not established); everything after `env -i` starts with only the listed variables, the pins last. `/usr/bin/env` itself starts with the host's environment, with the dynamic loader's and glibc's variables whose empty value does nothing laid over it empty (`LD_PRELOAD`, `LD_LIBRARY_PATH`, `LD_AUDIT`, `LD_DEBUG`, `LD_PROFILE`, `LD_BIND_NOW`, `GLIBC_TUNABLES`, `GCONV_PATH`, `LOCPATH`, `DYLD_*` and the rest of `LOADER_BLANK`). The three that act when merely present (`LD_TRACE_LOADED_OBJECTS`, `LD_SHOW_AUXV`, `LD_DYNAMIC_WEAK`) cannot be blanked, since the host can only add a variable: one set changes what `env` itself does (it prints and does not run the shell, say), never what runs after it, and a measurement that does not answer as expected is UNKNOWN | `bounded`, `cleanAssignments`, `LOADER_BLANK` |
| `HOME` and `XDG_CONFIG_HOME` are passed as they are, so Git reads the person's global and system configuration and global ignore file, as 0.6.5 did and as the person's Git does: fingerprints of ordinary repositories do not change. Phase 2's own design drops global configuration; the released fingerprint does not | `cleanBaseOf` |
| A caller may add `LC_ALL=C` and nothing else; any other variable refuses the process before it starts | `callerEnvAdmitted` |
| The limit probes start the same way; GNU `timeout` is given to the limit script by absolute path; a probe's `$0` is `cockpit-probe`, never the measurement's | `probeBound`, `boundScript` |

**Which programs run.** Once a load, the clean shell finds `git`, `stat`, `find`, `readlink`, `realpath`, `timeout`, `id` and `dd` with its own `command -v` (a builtin: nothing on PATH runs to answer) on the **absolute** entries of PATH only; an empty or relative entry names the current directory, which may be the repository, and is never searched. Until every check below has passed, the only programs that run are `/usr/bin/env` and `/bin/sh`, by absolute path, and the limit probes that run are the shell's own `ulimit`. Then, in this order:

- each program found, and `/usr/bin/env` and `/bin/sh`, is resolved to the file it is (every link followed) with the host's own `$.fs.stat`, which starts no process;
- none may lie inside the repository the session is in (below);
- owner and mode are read with `stat -L` (GNU or BSD form) by the system's own `stat`, `/usr/bin/stat` or `/bin/stat`, so the check does not depend on a program it has yet to check; where neither exists (NixOS, say), the `stat` found is used, after the repository check, and is then the one program run before its owner is known;
- each program and that `stat` must be a regular file owned by root or by the session's user, not writable by its group or others, and **every directory above it, to the root, and above the path it was found at** (a link in a directory others could write to is refused, though the file it leads to is root's), owned by root or that user and not writable by others (a directory its group may write to is accepted: on macOS `/usr/local/bin` often is, for the admin group); the user is `id -u`, by `/usr/bin/id` or `/bin/id`, run only once its own owner and mode were found to be root's and closed; an `id` that is not is never run and refuses nothing, and then only root's programs are trusted;
- only then GNU `timeout`'s version and `dd` under and without the 32 MiB cap, each by its absolute path (without `dd`, the memory limit is reported as not enforced);
- (the repository check) no program may lie at or below a directory of the session's that holds a `.git` entry (the session directory and every parent, along the path the session names and along its physical one), checked with `$.fs.exists` before any measurement process starts there (kept for the session directory where a repository was found, checked again for every process where none was, so a `.git` made later is seen; a path too deep to walk to the root refuses): a PATH entry inside the repository never supplies Git, and is not passed on in PATH either.

`stat`, `find`, `readlink` and `realpath` are required. Without `timeout` the limits still apply, without the group kill (as before). Without Git, no Git call starts; a session with no Git and no `.git` anywhere is outside every repository, as it was (a shell's "not found" was read that way), and one with a `.git` is UNKNOWN.

**An environment Cockpit does not measure in.** Twenty variables make the person's own Git use another repository, index, object store, configuration or attributes than it would find from the session directory (`GIT_ENV_MEASURED`: `GIT_DIR`, `GIT_WORK_TREE`, `GIT_INDEX_FILE`, `GIT_OBJECT_DIRECTORY`, `GIT_ALTERNATE_OBJECT_DIRECTORIES`, `GIT_COMMON_DIR`, `GIT_NAMESPACE`, `GIT_CEILING_DIRECTORIES`, `GIT_DISCOVERY_ACROSS_FILESYSTEM`, `GIT_SHALLOW_FILE`, `GIT_GRAFT_FILE`, `GIT_REPLACE_REF_BASE`, `GIT_CONFIG`, `GIT_CONFIG_PARAMETERS`, `GIT_CONFIG_COUNT`, `GIT_CONFIG_GLOBAL`, `GIT_CONFIG_SYSTEM`, `GIT_CONFIG_NOSYSTEM`, `GIT_ATTR_SOURCE`, `GIT_ATTR_NOSYSTEM`). The clean start does not pass them, so where one is set Cockpit's Git would measure something else: measurement is refused instead, with the name. Variables that only change what Git runs or where it writes (`GIT_TRACE*`, `GIT_SSH*`, `GIT_EXEC_PATH`, `GIT_EXTERNAL_DIFF`, the loader's) are simply not passed. A `HOME` or `XDG_CONFIG_HOME` that is set but not absolute, a PATH with no absolute entry, a required program missing, unresolvable, not trusted or inside the repository: each refuses too. A refusal stops every measurement process before it starts (`EnvironmentRefused`), and its words reach the fingerprint's UNKNOWN reason, the Stop record, `/cockpit doctor` and, for helpers, the deny.

**A helper's Git inspection.** The rebuilt command starts the same way, as single-quoted words: `'/usr/bin/env' '-i' 'PATH=…' 'HOME=…' ['XDG_CONFIG_HOME=…'] 'GIT_NO_LAZY_FETCH=1' 'GIT_ALLOW_PROTOCOL=cockpit-none' '<Git by the absolute path measurement found>' '--no-pager' …`, each command of a pipeline on its own. What this settles, against the Bash tool:

- **Its shell.** The Bash tool loads the person's aliases and shell functions (documented; on the development host a `find` function was there). A name with a slash is not looked up on PATH and is not an alias, so neither decides what runs, and none of the shell's exported variables reaches Git. A shell **function** with that exact name is another matter: bash (outside its POSIX mode) accepts a function named `/usr/bin/env` and runs it in place of the program, even when the word is quoted (verified locally with bash 5.2), and no simple command can step around a function (`command` and `builtin` can be functions too). Such a function can come only from the person's own shell start-up, not from a repository; it stays outside Cockpit's control (below).
- **The lazy-fetch pins** are environment variables now, as in measurement (Stage A item 3).
- **Its directory** is pinned with `-C` (Stage A), so the shell's directory still does not matter.
- **Argument boundaries:** every word is single-quoted from the parsed words (Stage A); the clean start adds only fixed words and values Cockpit read.
- **Refusal:** where no clean start is possible (the reasons above, or no Git found), inspection is refused with the reason.

What it does not settle, and was not changed: the host's **permission decision** is made on this rewritten command (documented), as it was on Stage A's. The Claude Code documentation says a rule matches the command text after it strips a fixed set of wrappers (`env` is not one), and that a quoted word or an absolute path does not match a rule written for the bare command; so a person's `Bash(git …)` rules matched neither Stage A's quoted command nor this one, and the permission mode decides (in the default mode, a prompt; a background helper's prompt is shown in the main session). Cockpit neither approves nor refuses on the host's verdict. **A check made before a permission prompt is not made again after it**: while the prompt waits, a gitlink or a partial clone that appears is still kept out by the command's own pins, but a clean/process filter driver configured meanwhile would run in `git diff` or `git status`. Refusing every inspection the host would ask about (a `tool.check` hook) would close that wait, and in the default mode would turn helper Git inspection off; that is your decision, not made here.

**The filter check gates the commands that apply filters.** A pass from `repoState` admits `status`, `diff` and a filtering `hash-object` only once `gitFiltersReliable` has accepted that pass (a second module-private mark, given only there); the callers already ran it first, and now the runner holds them to it.

**Admission by exact form.** The runner admitted, in Stage A, any arguments for an admitted subcommand. Since Stage B the words before the subcommand must be `GIT_SAFE` word for word and in order, then at most one `-C` with an absolute directory (`git --version` alone apart); and each subcommand is admitted only in the forms Cockpit writes:

| Subcommand | Forms admitted | Reads |
| --- | --- | --- |
| `rev-parse` | `--show-toplevel`, `--show-prefix` (from the session directory, no `-C`); `--git-path info/exclude --git-path info/attributes --git-path objects/info/alternates`; `--git-path objects/pack`; `--verify HEAD` | discovery |
| | `--verify --quiet <name>^{commit}` (the scoped rule's plain name only) | state |
| `config` | `--null --list`; `--type=path --get core.excludesFile` or `core.attributesFile`; `--bool --get core.symlinks` or `core.filemode` | discovery |
| `ls-files` | `-z --stage` | listing |
| | `-z`; `-v -z`; `-o --exclude-standard -z`; `-o -i --exclude-standard -z -- .` and `:(exclude)<prefix>` words | state |
| `ls-tree` | `-r -z --full-tree <HEAD or a full commit id>` | listing |
| `check-attr` | `-z --stdin filter` | state |
| `hash-object` | `--no-filters --stdin`; `--no-filters -- <paths>`; `-- <paths>` | state |
| `diff` | `<HEAD or a full id> -O/dev/null --no-renames --ignore-submodules=all --name-only -z --diff-filter=d` (or `=D`) | state |
| `status` | `--porcelain --untracked-files=all --ignore-submodules=all`; `--porcelain=v2 --branch --ignore-submodules=all` | state |

So `hash-object -w`, `diff --output=…`, `--ext-diff`, a revision expression, an option where a path belongs, `--ignore-submodules=none` or any other form is refused before it starts, pass or not. `stat`, `realpath`, `readlink` and `find` are admitted only in their exact forms too (`stat` with Cockpit's own formats and paths after `--`; `realpath -e -- <absolute path>`, and `realpath -m -- <absolute path>` for the paths orchestration tasks claim and name, which since Stage B also starts clean through the runner instead of by bare name: so where no measurement process may start, a claimed path cannot be canonicalised and locks everything, as an unresolvable path always did, and the lookup takes one of the two measurement slots, under a one-second group timeout; `readlink -z -- <path>` or, as its fallback, a path that begins with `./` or `/`). The census (`scripts/check-git-callers.mjs`) stays a separate text-level tripwire: it fails on a new site or call, and now also when the runner or its probes do not start clean, when the probe runs a program it found before the repository and owner checks, when the caller-variable check or the filter check's mark is gone or given anywhere else, when the measured names are not read exactly in order, when a measured name is not also refused for helpers, or when the process capability is reached through another name, a bracket (`$['process']`, with any quote) or destructuring (`const { process } = $`); the script tests its own patterns on sample lines first and stops if one does not fire (a pattern a substitution had made dead is how the bracket check was first written).

**The HUD after a failure before the repository is found** (Stage A item 9). A refresh in which Git failed or timed out before saying where the repository is replaces whatever line was shown with `not measured (state unreadable)`, never keeps a count or a `no repo` that may be stale; with no line yet, nothing is shown, except for an environment refusal, which shows `not measured (environment)` in any case (also after the repository was found). `no repo` is written only where the session is outside every repository (`outsideGit`): a repository that could not be verified, or no Git with a `.git` here, is `not measured (state unreadable)`. The Stop guard still decides from its own refresh's answer.

**`/cockpit doctor`** names how measurement processes start (the absolute PATH entries searched, Git's path, which of `HOME` and `XDG_CONFIG_HOME` are kept), or why none does.

## Refusal behaviour

| Where | A refused repository gives |
| --- | --- |
| Fingerprint (prompt baseline, goal-check guard, Stop guard) | UNKNOWN with the reason. No baseline; a goal check claimed ALIGNED is recorded UNKNOWN, in every Stop-guard mode; a passing Stop check is not recorded as verified; the task does not read DONE |
| Release check | no candidate (`CANDIDATE UNKNOWN`); no `status` runs |
| HUD | an explicit refused state with its reason |
| Stop with no task and nothing owed (`stopGuard: ENFORCE`) | a possible change: the check runs, its pass is not recorded as verified, and the task is held. The same where no repository could be verified and Git does not say the session is outside every repository (a failure, a timeout, no shell to set limits): only a repository read in full and found clean, or a session outside every repository, stops without a check |
| Helper inspection | denied with the reason; nothing is sent to the host |
| An environment Cockpit does not measure in (Stage B) | the same everywhere, with its reason: no measurement process starts; the HUD says `not measured (environment)`; a Stop with no task runs the check and holds the task |

Nothing is retried with weaker settings, without the check, or with `--ignore-submodules=none`. A missing object reached anyway (a race, or a state the check could not see) makes Git fail the command instead of fetching (where Git honours the pins), and the answer is UNKNOWN.

## Process-site coverage

`scripts/check-git-callers.mjs` reads the source and compares it with the checked-in census `scripts/git-callers.json`; CI runs it. It reads text, not a syntax tree, so it is a tripwire for review; the runtime admission is the guard. It fails on a new process site, a new `bounded` call, a new call of a closure that runs Git (with literal or computed arguments), any use of the process capability other than a direct `$.process.run(` call, `child_process`, `eval` or a dynamic `import()` in any hooks module, and a broken invariant: only `hooks/register.tsx` starts processes, at exactly 10 sites (11 in Stage A; `canonicalIn` now runs through `bounded`); every program in every `bounded` call is a measurement program; a pass is created only in `repoState`; `auth` is only ever a pass or the check's own listing capability; the helper's environment check reads exactly `GIT_ENV_REFUSED`, in order. Since Stage B also: `bounded` and `probeBound` start their processes as `/usr/bin/env -i` with the loader's variables blanked, `bounded` refuses a caller's variables other than `LC_ALL=C`, the measurement environment check reads exactly `GIT_ENV_MEASURED` in order, every one of those names is also in `GIT_ENV_REFUSED`, and the clean base reads `PATH`, `HOME` and `XDG_CONFIG_HOME` and nothing else. (The plugin test runtime imports only the plugin's own modules, so a test cannot read source files.)

The sites that are not measurement (`pollLedger`, the telemetry maintenance, the audio player, the router, the verification script) still start with the host's environment and find their program on its PATH: they run no Git and read no repository state, and the person's own programs are theirs to choose. Git that the host runs as typed is outside Cockpit's execution guarantee: the commander's own commands (Cockpit only decides whether one is held, so a commander's `git status` in a submodule repository can still enter the submodule), any other Bash, every helper's Git when orchestration is off, and Claude Code's own Git calls.

## What v0.6.6 protects, and what it does not

**Protected, as designed and tested against a fake host:** no Cockpit Git command that reads repository state starts in a repository with a gitlink in its index or in a commit compared without being measured, or with any partial-clone configuration or promisor pack; no Git command outside a closed list of exact forms starts at all; every Cockpit measurement process starts with a clean environment of listed variables, the pins last, every program by absolute path from an absolute PATH entry, trusted by owner and mode and never inside the repository; an environment in which the person's Git would see another repository or configuration is refused, never measured; no `status` or `diff` examines a submodule; a helper's inspection starts Git the same way; a refusal is never a clean tree, a zero count, an accepted goal check, a verified Stop check, DONE, a release candidate or an allowed inspection.

**Closed by Stage B** (Stage A's numbering): 1, the inherited environment of measurement processes (the clean start, and the refusal where a Git variable would make it measure something else; `GIT_DIR` alone is now refused rather than left to the root check); 3, helper commands' weaker lazy-fetch pins; 8, unchecked arguments of admitted subcommands; 9, the stale HUD line. Item 2 is closed for what reaches Git (the helper's command starts it clean) but not for the Bash tool's shell itself (below).

**Not protected:**

1. **The Bash tool's shell, for a helper's command.** The command starts from the shell the host runs, with the person's profile loaded: its aliases and PATH no longer decide what runs (absolute names) and its exported variables no longer reach Git, but a shell function named `/usr/bin/env` (bash accepts one, verified locally), shell options and traps in that snapshot, and the dynamic loader's variables of the shell's own environment for `/usr/bin/env` itself (a helper command cannot blank them as measurement does), are outside Cockpit's control. What it reaches is the person's own shell configuration, never the repository's.
2. **The wait before a permission prompt is answered.** A helper's command is checked when Cockpit sees the call; the host may run it after a prompt, with no bound. In that wait the command's own pins still keep Git out of a submodule (`diff`, `status`) and stop a lazy fetch, but a clean/process filter driver configured meanwhile would run, and `log -p`/`show` against a new gitlink rest on `diff.submodule=short` (item 5). Refusing what the host would ask about is the owner's decision (above).
3. **Check-then-use windows in measurement.** The check runs before the commands that need it, the filter drivers are read again right before a fingerprint's `diff` and a release check's `status` (the HUD's `status` and a helper's command use the check's own read), and `repoMoved` stops a fingerprint or a release check that saw a state change; none undoes a command that already ran. A gitlink, promisor remote or filter driver that appears between the last check and a `status` or `diff` of the same measurement is reached by that command, behind the pins only. The HUD has no repeat check. On Git older than 2.45 (and builds without the backported switch), only `GIT_ALLOW_PROTOCOL` stands behind a missed partial clone.
4. **Promisor packs in an alternate object store** are not listed; the pins still apply.
5. **A `*` helper command that names an older revision** is not parsed for revisions; a gitlink there is kept out by `--ignore-submodules=all`, `diff.submodule=short` and `submodule.recurse=false`, not by the check. Whether those hold on `log` and `show` is for the real-Git acceptance.
6. **The person's global and system Git configuration** is read by measurement, as in 0.6.5 (so stamps and ignore rules match the person's Git); a hostile one needs write access to the person's home or the system, and the keys Cockpit pins are set on the command line, which beats configuration (measured for `core.fsmonitor` and `core.hooksPath`). A `HOME` inside the repository makes the repository's file the global configuration; that is the person's own arrangement (a home directory kept in Git) and is not refused.
7. **Installations that need more than the allow-list** (`LD_LIBRARY_PATH` for a Git in a custom prefix, a relative PATH entry for Git): measurement is UNKNOWN there, with the reason, never run with the inherited environment. Which layouts need it is for the acceptance (Homebrew, Nix, distribution Git).
8. **Programs the clean shell finds** are trusted by owner and mode at load: a program replaced later by its owner, or by root, is not checked again until Cockpit loads again. A program owned by the session's user (Homebrew, `~/.local/bin`) is trusted like the user's own Git, and a directory its group may write to is accepted. Where the system has no `/usr/bin/stat` or `/bin/stat`, the `stat` found on PATH (outside the repository) runs once, to read owners, before its own owner is known. `/usr/bin/env` and `/bin/sh` themselves run before they are checked (they are what the checks run in); a replaced one of those is a compromised system.
9. **A repository with no commit yet and a configured filter driver** (a global Git LFS install, say): helper inspection is refused with the general identity reason, as in 0.6.5, because the filter check lists HEAD's tree.
10. **Behaviour on real Git and in a real host** of every pinned argv, of `/usr/bin/env -i` and of the rewritten helper command: tested here only against a fake host that models Git and the host.

## Latency

Target (owner decision V6): added overhead against 0.6.5 at most 250 ms at the 95th percentile and 500 ms at the 99th, warm and cold reported apart. Measured on the development host (Linux, 4 vCPU, Git 2.47.3, Node 22.23.3), outside the host, against four ordinary repositories: a clone of this repository (236 paths) and synthetic ones of 2,000, 20,000 and 45,000 paths (the last near the stage listing's 4 MiB ceiling). Warm: 100 runs per sequence (Stage A: 200). Cold: the page cache dropped before each of 40 runs, so the 99th percentile is the maximum.

**Stages A and B together.** Per run: Stage A's added processes, started as Stage B starts them, plus, for every process 0.6.5 already ran in the sequence, its Stage B start minus its 0.6.5 start, timed as a pair. How many processes a sequence runs comes from Cockpit's own chunking (counted with the test host on a clean tree: a fingerprint 31, 43, 178 and 367; a release check 24, 36, 171 and 360; a HUD refresh 14). Bold: over the target. **A fingerprint is within it at every size, warm and cold; the critical path while a release review is pending is within it up to 20,000 paths and over it at 45,000.** The clean start costs about 0.22 ms per process (mean of 4,000 pairs; 0.57 ms at the 95th percentile), so at 45,000 paths it adds about 185 ms to the critical path, and Stage A's own processes about 188 ms. The warm 99th percentile at 45,000 paths (666 ms) holds one run with a 511 ms pause in the paired starts, not repeated cold. Once a load, the probe (the lookup, `id -u`, and `stat -L` on every program and the directories above them, with `realpath` standing in for the host's `$.fs.stat`) takes 38 ms warm and 40 ms cold at the 95th percentile. Outside a repository, a HUD refresh now also asks `outsideGit` (about three processes) before it writes `no repo`, and the repository check walks the session directory's parents with `$.fs.exists` for each process there (not measured: host calls); inside one, that walk is made once. Not included: the host's own cost of starting a process and returning its output (estimated at about 2 ms per process in 0.6.5's research, so more at every size), and waiting for one of the two measurement slots. A measurement through a real host is part of the acceptance.

The cost grows with the processes a measurement runs, which a clean tree of 45,000 paths makes about 360 per measurement (the tracked files are hashed and inspected in chunks of 400, three processes a chunk). Meeting the target there is a design decision, not made here: fewer, larger chunks (by bytes rather than by count) would cut the processes 0.6.5 already runs as well as the clean start's share, without weakening an invariant, but they change measurement's per-process time and output bounds and need their own review.
